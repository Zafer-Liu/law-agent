# 民事类案检索实验报告

Railway PostgreSQL 17.12 和 pgvector 0.8.7 已存入 1,000 份民事裁判文书及 1,000 条 `qwen3.7-text-embedding` 的 1024 维向量。10 个查询均完成 Top 5 检索。本地 PostgreSQL 18.6（PGlite 0.5.16）上的 BGE-M3 和 BM25 结果用于对照。

## 数据与方法

- 案例库源文件为 `civil_database_1k.json`，SHA-256 为 `a6a13437876d12f882696e499a0fec379d4bb9962a475c0a812a7d84694fd146`。以 `uniqid` 关联文书与向量。报告中的文书编号对应源数组的顺序，从 1 开始。
- 保存标题、全文、诉讼事实、裁判理由与结果。检索文本取案由和诉讼事实。255 份文书的诉讼事实字段为空，先从全文提取事实段，无法识别时取标题。案由标签来自本次六类查询的标题词表，其他标题可能没有标签。
- 第 2 个查询对应库内文书 11，第 3 个查询对应库内文书 15。三种方法均在排序前排除各自原案。不同审级的关联文书仍可能同时存在于库中。
- **原文 BM25** 用完整查询正文计算中文字符二元组 BM25。**争点 BM25** 用事先凝练的争点文本做同样的检索，已知同案由候选分数乘以 1.5。**BGE-M3** 用案由和查询正文生成向量，PostgreSQL 用 pgvector 的 `<=>` 按余弦距离精确排序。三种方法采用同一份文书检索文本。
- 对四个排名的 Top 3 取并集，按“查询—候选”配对评审，共 101 对。`2` 表示法律关系和主要争点实质可比，`1` 表示同类或部分要素可比，`0` 表示法律关系或争点不符。评审结合文书的事实、证据和裁判理由。第 4、5 名保留排名和分数，未纳入评分。

## 效果对比

| 检索方法 | 首位为实质类案 | 前三位实质类案占比 | 前三位至少一个实质类案 | 前三位案由标签相同 |
| --- | ---: | ---: | ---: | ---: |
| 原文 BM25 | 4/10（40%） | 10/30（33.3%） | 6/10（60%） | 23/30（76.7%） |
| 争点 BM25 | 5/10（50%） | 13/30（43.3%） | 8/10（80%） | 30/30（100%） |
| PostgreSQL + BGE-M3 | 7/10（70%） | 12/30（40.0%） | 7/10（70%） | 26/30（86.7%） |
| PostgreSQL + `qwen3.7-text-embedding` | 4/10（40%） | 11/30（36.7%） | 7/10（70%） | 28/30（93.3%） |

数据集中只有 10 个查询，其中 4 个是民间借贷。上述比例描述本次候选池。全库相关文书总量未知，无法计算全库召回率。争点 BM25 同时调整了查询文本和案由权重，指标差异无法归因给其中一项。人工提炼争点也会影响实际使用时的效果。

## 检索提升方向

1. **先抓住法律关系、所求款项和核心证据。** 对欠款类查询标明款项来自货款、租金、劳务报酬还是借款。区分“欠款确认”和“结清证明”，同时保留诉请、争议时段、签字身份、交付方式及付款凭证。对于基于旧裁判的结论，还应核对法律适用时间与规则变化。
2. **融合两路候选，再按争点重排。** 用案由对边界清晰的查询加权，对贷款、租赁等存在相邻案由的情况保留跨案由候选。结合向量与 BM25 的排名，例如使用 RRF，再按关键争点与证据重排。可把 Q6 的劳务报酬误匹配和 Q3 的饮料供货误匹配作为困难负例。
3. **分开验证文本处理与排序。** 单独比较原文、争点摘要、去身份信息文本及段落向量。追加独立查询与多位评审者，扩大候选池后复测 `qwen3.7-text-embedding` 的首位命中率和前三位精度。在重复实验中记录模型和文本版本，并更严格地剔除原案及其跨审级重复文书。

从法晓 `/app` 的「类案检索」进入项目内功能。数据库配置、入库命令与 API 用法见 [接入与复现](README.md)。
